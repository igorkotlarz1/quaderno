# M4 – dziennik (co się wysypało i jak to obeszliśmy)

- **Odpowiedź jako łatka, nie cała lekcja.** Ręczny prompt zwraca całą lekcję i import ją podmienia. Przy jednym kliku
  uczeń może pisać dalej, zanim Claude odpowie, więc serwer prosi o poprawki po `id` (structured outputs, schemat
  z Pydantic), a aplikacja nakłada je tylko tam, gdzie od wysłania nic się nie zmieniło.
- **Schemat bez `$ref`.** Pydantic generuje `$defs`/`$ref` i tytuły; do API idzie wersja „rozwinięta”, z
  `additionalProperties: false` i wszystkimi polami wymaganymi (puste = `null`). Sprawdza to test.
- **Modele:** Haiku 5.5 do lekcji (tanie poprawki), Sonnet 5.5 do oceny tygodnia, z wbudowanym w API przełączeniem
  na inny model, gdyby odmówił (beta `server-side-fallback`). Haiku nie ma takiego przełączenia: odmowa to błąd w logu.
- **Koszt to szacunek.** Liczony z cennika w `app/llm/cost.py` (tokeny myślenia są w tokenach wyjściowych);
  nieznany model liczymy po stawce Opus, żeby nigdy nie wyszedł „za darmo”. Dokładny rachunek jest w konsoli.
- **Bramka bez klucza.** CI nie ma klucza API i nie powinien wydawać pieniędzy, więc bramka M4 idzie na zastępczym
  „Claude” (`LLM_FAKE=true`, `app/llm/fake.py`), który odpowiada jak API według stałych reguł. Prawdziwe wywołanie
  sprawdza runbook na Optiplexie.
- **Bramka M3.5 po M4.** Zakładka „Uzupełnij z Claude” ma teraz zagnieżdżone „Koszty Claude”, więc selektor
  `#t-llm summary` trafiał w dwa elementy; testy używają `#t-llm > summary`.
